# Contributing to Awesome README

Thanks for helping make this directory more useful! Contributions of README and GitHub-profile resources are welcome, including websites, open-source projects, generators, services, guides, templates, and creative examples.

## Before you submit

1. **Check that the resource fits.** It should help someone create, improve, or maintain a README, GitHub profile README, or an asset commonly embedded in one.
2. **Search this list first.** Avoid duplicates; if a resource belongs in another category, suggest moving it instead of adding it twice.
3. **Check the link.** Use the canonical project or product URL (prefer its official website or source repository). Confirm that it loads and that the project is not clearly abandoned or unrelated.
4. **Write a neutral description.** Say what the resource does, not that it is “the best” or “the most amazing.”
5. **Choose the best category.** If it genuinely serves two distinct purposes, suggest a second listing only when that materially helps readers discover it.

## Add a resource

Open a pull request that adds one table row in the relevant section of `README.md`:

```markdown
| [Resource Name](https://example.com/) | A short, specific description of what it helps users do. |
```

For an open-source project with a separate demo, link the name to the demo and add a `[source]` link when useful, or link directly to the repository. Keep descriptions concise (ideally one sentence) and use sentence case.

If there is no suitable category, propose a new one in your pull request description. Prefer a focused category over a catch-all section.

## What makes a good addition?

- It is directly useful for README files, GitHub profile pages, or their graphics and widgets.
- It is publicly accessible and has a clear purpose.
- The link is the canonical destination and works without requiring private access.
- The description is accurate, concise, and understandable to an English-speaking audience.
- It is not just a generic tool with no clear README use case.
- Any hosted service, API, or third-party dependency is represented accurately; do not imply that a service is free, permanent, or maintained unless that is clear from its own documentation.

## Organization and style

- Keep entries in the most relevant category and in a readable, consistent table.
- Use descriptive link text; do not use “click here.”
- Do not add tracking parameters, referral links, or promotional copy.
- Avoid unsupported claims and unverifiable popularity rankings.
- Use the project’s official name and avoid unnecessary emoji.
- Check spelling, Markdown formatting, and links before submitting.
- Do not add personal information, access tokens, or other secrets.

## Pull request checklist

- [ ] The resource is relevant and not already listed.
- [ ] The destination is canonical and working.
- [ ] The description is brief, accurate, and in English.
- [ ] I added it to the best existing category (or explained a proposed category).
- [ ] I checked the Markdown formatting and preview.

## Broken links and updates

If a link is broken, a project has moved, or an entry needs a correction, please open an issue or submit a small pull request with the updated canonical URL. If a service appears to have shut down, include evidence or context so maintainers can review the listing.

## Code of conduct

Be kind and constructive. Contributions should follow GitHub’s [Community Guidelines](https://docs.github.com/en/site-policy/github-terms/github-community-guidelines) and respect project maintainers and other contributors.
